# نظام رصد السلوكيات ومتابعة التحصيل
إعداد: **الأستاذ خليل البلوشي**

## التحديث
- دخول برمز سري دون حد الثمانية أحرف، وإرساله في جسم الطلب بدل عنوان الرابط.
- حفظ متحقق منه وتعديل وحذف عبر خادم موحد، ومعرف ثابت للمشاركة.
- منع اختلاط أنواع المتابعة، وفصل المتابعة التحصيلية عن المخالفات السلوكية.
- منع تعارض تحميل الشعب، وتوحيد تصنيف السلوكيات، مع تحديث التقارير وتسجيل الخروج.
- لا يُفهم تصنيف نصح/تنبيه/إنذار باعتباره قرارًا تأديبيًا آليًا أو لائحة وزارية.

## تركيب Google Apps Script
1. احتفظ بنسخة احتياطية من ملف Google Sheets.
2. انسخ `Code.gs` كاملًا إلى مشروع Apps Script المرتبط بالجدول.
3. أضف في إعدادات المشروع ← خصائص النص البرمجي:
   - `ACCESS_CODE`: رمز سري قوي، لا تضعه في المستودع.
   - `SPREADSHEET_ID`: معرف جدول البيانات، مطلوب إذا كان المشروع غير مرتبط بالجدول.
   - `SHEET_NAME`: اختياري؛ الافتراضي `SBT_Reports`.
4. شغّل `setupSystem`؛ ينشئ ورقة مخصصة دون تعديل أوراقك الأخرى.
5. لنقل التقارير القديمة: أضف `LEGACY_SHEET_NAME` باسم الورقة القديمة ثم شغّل `migrateLegacySheet`. تُنسخ البيانات إلى الوجهة مع الحفاظ على الأصل، ويُرفض الترحيل إذا كانت الوجهة تحتوي تقارير. إذا كانت العناوين غير معروفة، يتوقف الترحيل دون تغيير بيانات المصدر.
6. من «نشر ← إدارة عمليات النشر» حدّث **النشر الحالي** إلى إصدار جديد للمحافظة على رابط الاتصال الموجود في الصفحتين. عند إنشاء نشر جديد، استبدل قيمة `GOOGLE_SHEET_URL` في `index.html` و`reports.html` بالرابط الجديد.
7. افتح الموقع وسجّل الدخول باستخدام قيمة `ACCESS_CODE`، ثم اختبر تقريرًا واحدًا وتأكد من ظهوره في الورقة والتقارير المحفوظة.

## حدود التشغيل
الواجهة ثابتة على GitHub Pages والخادم على Google Apps Script. تحديث المستودع لا ينشر Apps Script تلقائيًا. أسماء الطلبة الموجودة في ملفات المستودع متاحة لمن يستطيع قراءة تلك الملفات؛ شاشة الدخول تحمي عمليات الخادم فقط. حصر النشر بحسابات المؤسسة يحتاج آلية تسجيل دخول متوافقة مع واجهة الموقع الخارجية؛ لا تغيّر صلاحية النشر دون اختبار الاتصال.

بنية الورقة: المعرف، التاريخ، الطالب، الشعبة، نوع التقرير، السلوكيات، الملاحظات، الإجراء، وقت الحفظ، آخر تحديث.
